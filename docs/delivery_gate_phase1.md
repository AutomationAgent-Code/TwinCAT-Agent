# 写入链路交付追踪 — 第一阶段

## 已验证的修复

- 注释、命名和框架模板规范改为建议；语法结构和确定错误保留阻断。
- 声明解析在所属对象范围内求解整数 CONSTANT 数组边界。支持前向常量引用、
  加减乘、括号、一元符号及多维边界；限制表达式长度、节点数、递归深度和数值范围。
- 可变变量、循环引用、未知表达式不猜值；不跨对象借用同名常量。
- 已知数组边界不一致报告确定类型错误，未知边界仍报告能力不足。

实际案例回放：2026-09-12 17:58 的 MAIN 成对写入候选，使用该项目对话台账保存的
FB_TcpClient / FB_PID / 枚举声明作为只读依赖。修复后离线 review_candidate 返回
approved=true、findings=[]。这不是当前 XAE 的编译或写入验证，也不是在线验证。

## 深层语义分级进展

统一策略已接入 review_dependencies，由 plc_preflight 与写入依赖审核共同使用。
仅在语句解析状态为 parsed 时，把明确枚举的能力提示降为 warning：数组边界证据、
原生整数目标位宽、已知指针类型的生命周期、引用绑定，以及常量按引用传递的编译选项。
原始 semantic_review 仍可为 approved=false，semantic_evidence 仍为 incomplete；
顶层 approved 仅表示允许源码流程，不表示完整语义验证或上线许可。
缺失符号、依赖不可用、未知的新诊断及 syntax-unsupported 不降级。

## 尚未交付的部分

- 尚未将所有深层语义提示逐项分类；当前严格限定已审查的提示集合。
- syntax-unsupported 不可整体放行，它可能意味着解析器未能完成语法检查。
- 未知符号、缺少依赖与语法已经通过但深层语义未知需要进一步分开。
- 安装版同步、当前 XAE 测试对象的写入/编译闭环尚未执行。

本阶段不声称完整方案完成，不自动修改用户 PLC，不改变审批或运行时权限。
