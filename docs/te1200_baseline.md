# TE1200 静态分析基线

本规则适用于 TwinCAT Agent 新建或修改的 PLC 代码。Agent 自有规则不依赖 TE1200 授权，
不加载或分发厂商反编译代码、不修改授权校验。编译成功不等于通过
TE1200 静态分析；只有实际执行了静态分析并取得结果时，才可以声称通过。

## 必查规则

### 正确性与安全

- `SA0001`：不可达代码。
- `SA0004`：同一输出存在多处写入。
- `SA0006`：多个任务写入同一变量。
- `SA0028`：内存区域重叠。
- `SA0039`：可能解引用空指针。
- `SA0040`：可能除以零。
- `SA0103`：并发访问非原子数据。
- `SA0145`：引用可能未初始化。
- `SA0172`：可能越过数组边界。

### 接口与类型

- `SA0020`：REAL/LREAL 转换可能截断。
- `SA0026`：字符串赋值可能截断。
- `SA0037`：写入输入变量。
- `SA0038`：读取输出变量。
- `SA0054`：直接比较 REAL/LREAL 是否相等。
- `SA0107`：调用时缺少形式参数。
- `SA0171`：枚举应使用严格类型属性。

### 控制流与可维护性

- `SA0027`：重复名称。
- `SA0033`：未使用变量。
- `SA0075`：`CASE` 缺少 `ELSE`。
- `SA0076`：`CASE` 缺少枚举常量覆盖。
- `SA0078`：`CASE` 没有实际分支。
- `SA0105`：多次实例调用（Agent 周期调用规范独立执行，不等同官方属性驱动的规则）。
- `SA0140`：保留了被注释掉的语句。
- `SA0167`：临时功能块实例。
- `SA0175`：可疑字符串操作。
- `SA0178`：认知复杂度过高。
- `SA0179`：对象间耦合过高。

## Agent 执行要求

1. 写代码时主动规避上述问题，不以 pragma 隐藏真实缺陷。
2. 对输出、跨任务共享变量、指针/引用、数组边界和除法做重点审阅。
3. 写前约束由 `tc_template/plc_constraints.py` 注入系统提示；`plc_static_constraints`
   可按 SA 编号查询要求和真实检查覆盖。写后运行 `plc_static_analysis`，报告 TCSA 编号、对象和位置。
4. 若没有运行 TE1200，明确写明“未执行 TE1200 静态分析”，不得用 PLC 编译结果代替。
5. 安全相关规则（尤其多处输出写入）不得为消除告警而简单禁用。

## 执行层

现有 `review_write_candidate` 在实际写入前执行 TCSA 检查；高置信度硬错误
（直接给输入赋值、字面量零分母）阻止写入，包括同一行分支内的直接赋值。
嵌套注释和字符串不会被当作可执行代码；非零小数分母不误报为零。
成员的本地声明用于区分同名父级输入。CASE 缺少 ELSE、临时定时器、浮点相等、
未使用变量和复杂度等以建议反馈，需审阅后处理。

`plc_static_analysis` 返回错误时不能计入成功完成证据；未知诊断数量也不能当作零错误。
无编译器语义的规则（任务并发、地址重叠、动态数组边界、指针生命周期等）仍是
写前设计要求及人工/Agent 审阅项，不能据 TCSA 无告警宣称已验证。

参考源：Beckhoff 官方 `TE1200 TwinCAT 3 PLC Static Analysis` 文档。
