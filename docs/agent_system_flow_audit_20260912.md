当前不能判定对话流程与授权机制已经闭环。已有多项有效保护，但跨轮授权、部分执行后的事实报告、多面板审批、未知执行结果的恢复仍存在断点。

证据等级：**回放**＝临时 SQLite/模拟接口的可执行测试；**静态**＝代码路径确认，尚未端到端操作；**历史现场**＝上一份审查已读取的会话与运行证据，不表示当前设备状态。

|---|---|---|

| PID/进程启动标识/工程/端点/会话变化 | 7 个身份维度回放均拒绝 | 非运行时临时审批未使用同一完整上下文校验 |

| uncertain → 下一轮同义重试 | SYS-04 台账层回放失败 | 新 run/call 可重新获得 execute；不代表其它门禁必然放行 |
| 部分完成 → 下一动作被拒绝 | 历史现场失败 | 最终仅报告未授权，没有列出已完成动作与未恢复状态 |
| 单动作计划完成 → 请求后续独立审批 | 静态 + 历史现场断点 | completed active plan 仍阻挡范围外动作，未进入新审批 |
| 用户停止 → 下轮继续 | 既有上下文保留、孤立工具结果修复测试通过 | 停止不代表已派发 COM/远程动作物理取消；恢复信息与部分状态需统一 |
| 后端重启 → 在途恢复 | 既有台账测试将 running 标记 uncertain | 必须查询实际状态后恢复，不只补全模型消息 |
| XAE 关闭/身份变化 | 既有模拟退出与禁止改绑测试通过 | 真实关闭发生在各派发阶段的竞态尚未逐个验收 |
| 新面板连接 → 保留另一对话授权 | 静态缺陷 | initialize_session 无 thread 参数使同项目全部计划失效 |
| 同工程多个对话 → 并发执行 | 既有 claim/队列原子性测试通过 | 原子领取不证明设备操作资源互斥或审批独立 |
| 前台 → 后台执行入口 | 静态差异 | 后台无法弹出审批；应明确等待审批/移交，不建议放宽权限模式解决 |
| UI 允许 → 后端确认 | 静态缺陷 | WebSocket 不可用仍显示“已允许”；缺少确认 ACK 驱动状态 |
| 另一项目同名 main → 临时审批响应 | 静态风险，未证明实际可利用 | 普通审批只检查 thread_id，需补 DB/project/owner 绑定 |
| 压缩 → 恢复上下文 | 既有并发追加、摘要保留测试通过 | 摘要不能作为授权；版本化执行事实需从台账恢复 |
| 分支/复制会话 | 既有上下文与事件隔离测试通过 | 授权不继承的跨入口完整验收尚缺 |
| 状态读取 → Build 审批 | 既有令牌/动作/状态变化保护通过 | SYS-05 接受混合工程身份的快照 |

| 外部 MCP → 超时 | 静态风险 | 通用 error 未区分派发前失败与派发后结果未知 |

## 优先修复项及定位

### P0：部分执行后的终态事实必须准确

历史现场：一次验证写 `MAIN.bEnable=True` 已回读成功，恢复 False 被拒绝，最终却只报告权限未确认。详见 `docs/agent_logic_audit_20260912.md`。上一轮读取到 True 不代表本报告生成时仍为 True。

`tc_agent/backend.py:2865` 的 stop_reason 分支直接写最终消息/返回；`2390` 每轮新建 CompletionEvidence。应统一所有成功、失败、取消、超时出口，从持久台账生成“已执行/未执行/未知/待恢复/未验证”。不能自动把恢复动作当作已获授权，更不能自动重试未知写入。

### P1：授权必须是有身份、有步骤、有生命周期的计划

- SYS-01：`tc_agent/authorization.py` 的 explicit_report_actions。不应由自由文本推断真实操作权限；状态叙述与待批准动作分离。
- SYS-02/03：`plan_allows_action` 与 `consume_action`。每一步使用独立 step_id、前驱和状态，不能仅靠工具名/参数的集合。
- 后续授权断点：`tc_agent/backend.py:2643`。计划结束后应允许提出新的独立计划，不能隐式继承旧权限，也不能永久阻断所有新审批。
- 多面板：`tc_agent/backend.py:3025` 项目级失效范围过宽。身份变化与单连接变化分别处理，保留必要的安全失效，但不要误撤销无关执行者。
- 临时审批：`tc_agent/backend.py:3331` 补充 project/store、thread、owner、请求 nonce、参数摘要；严格要求 allow 为布尔值。运行时计划已有上下文核验，不应误称所有审批均能跨项目放行。
- UI：`tc_agent/static/index.html:2390` 附近的 decide。发送成功并不等于批准成功，更不应在未发送时显示批准。等待 ACK；超时/过期/重连明确标记。

### P1：未知结果和构建事实不能靠重试或猜测消除

- SYS-04：`tc_agent/runtime.py:28`、`tc_agent/conversation_store.py:1061`。防重放键包含 run/call，只覆盖同一调用。建议持久 operation_id 与未决操作阻塞，按目标/资源识别需要核对的后续动作；不能永久禁止合法重复命令。
- SYS-05：`tc_agent/build_execution.py` 的 capture_build_state。各返回来源身份必须一致；执行锁内重新验证，派发时传递预期工程身份。
- SYS-06：同文件 execute_plc_build。保留底层“未派发/已派发/完成/未知”事实，不无条件改写为执行过。
- SYS-07：同文件 verify_build_plan。纯校验与原子消耗拆开，只有实际执行预约才能消耗。
- Rebuild：`tc_template/_native_bridge.py` 的 _build 与 `tc_agent_vsix/XaeBuildPipeService.cs`。必须把本次构建生命周期与诊断关联，不能仅凭历史 Done/LastBuildInfo。
- 外部工具：`tc_agent/mcp_client.py` 的 call 异常处理。执行后连接中断按 unknown/uncertain 返回，结合远端请求 ID 或读后核对；不默认重发。

### P2：执行入口与证据呈现统一

`tc_agent/backend.py:1837` 后台审批不支持；应提供“等待人工审批/转前台”状态，不诱导用户切到更宽模式。组合工具保留每步事实，部分批准不得执行依赖不满足的后续动作。跨轮 CompletionEvidence 应引用工程/源码版本、目标和验证时间；匹配几个“完成”词不能替代结构化验收。
