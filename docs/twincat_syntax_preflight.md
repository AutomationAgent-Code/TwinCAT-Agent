# TwinCAT ST 生成前契约与写前检查

本功能使用自有 Python 语句解析器和有界语义检查器，不依赖 IronPLC，不启动额外 TwinCAT 实例，不调用编译器。不是完整 ST 编译器，不能宣称覆盖 TwinCAT 全部语义。

## 流程

1. `GenerationContext` 在每次 PLC 模型请求前附带 `syntax_rules` 和 `syntax_contract`，包括上下文压缩后；项目读取失败仍保留语法规则。先提供项目声明、编译器配置、库和模板信息，缺失内容显式查询。
2. `plc_syntax_templates` 返回相同的版本化契约与对象模板。规则覆盖 XAE 声明/实现分区、DUT、方法/属性/Get/Set、类型转换、枚举、依赖和验证含义。
3. 写入候选先经过本地语法检查，再核对精确 PLC 项目的实时依赖。已知枚举成员在 CASE、条件和赋值中均检查；依赖不完整不能冒充不存在。
4. 明确语法错误不能通过关闭风格门禁绕过，也不能被增量审核降级为历史警告。写前语义审核检查完整候选内容；语义不支持或依赖无法确认也阻止放行。风格历史债务仍由独立的增量风格门禁处理。
5. 写后 `verified` 只表示文本回读，`verification_scope=saved_text_readback_only`，`compiler_verified=false`。最终依据仍是当前 XAE 的完整成功编译，不自动下载、激活或启动。

## 已覆盖的确定性检查

- XAE 不应出现的对象闭合关键字、代码块和括号配对。
- 未闭合字符串、WSTRING 和嵌套注释；注释与字符串内的示例不误报。
- `DINT(x)` 等数字类型名伪转换；声明中的 `INT(0..100)` 子范围不误报。
- `TYPE#(表达式)`、实现区声明，以及已解析 GVL/枚举成员和整数直接赋枚举。
- Pratt 表达式解析、嵌套 IF/CASE/FOR/WHILE/REPEAT、操作数、分号、THEN/DO、命名参数及参数方向。
- 已解析声明中的标量赋值/初始化、整数常量范围、BOOL 条件、数组维数/索引类型/常量越界。
- 项目 FB 字段、输入/输出/IN_OUT 参数和公开方法签名；成员实现可合并父对象声明与局部作用域。

## 整批候选审核

`plc_preflight(candidates=[{name,path,declaration,implementation}, ...])` 只读检查 1..100 个完整候选对象，合计不超过 200 万字符。按 PLC 项目隔离覆盖层，先用同批候选声明，再读取缺少的现有依赖；同名歧义拒绝。只缓存本次审核的相同依赖读取。

例如同时新增 `E_State.Starting` 并修改 MAIN，审核按新的枚举候选判断，不因旧工程暂时缺成员而误报。结果含候选哈希和逐对象报告；`approved=true` 只表示通过当前支持范围的审核，不是编译证明、写入凭据或事务提交。本接口不会批量写入；实际写入仍逐次校验实时基线。批次成员覆盖及复杂类型仍存在下述边界。

转换使用 `SOURCE_TO_TARGET(x)` 或 `TO_TARGET(x)`。时间转换必须核对单位；`TIME()` 可能是库函数，不应作为普通类型名转换被一概禁止。

## 诊断和修复

XAE 的 Medium 级别不直接等同于语法警告。失败构建中，带文件和行号的明确 `expected` / `Unexpected token` 等诊断归为错误，保留 `raw_error_level` 和 `severity_inferred`。普通枚举隐式转换警告不因构建失败而提升。

旧扩展的 pending 仅在匹配已知完整 UI-thread 协议时恢复：原错误数为 0、警告列表计数一致、5 次读取、固定的无错误提示、明确可用且没有截断，并确实从中识别出错误。保留原 pending/message 和恢复原因，构建依然失败。其他 pending/截断绝不清除。`plc_build` 和 `plc_verify` 共用修复预算，无源代码进展不重复构建；诊断采集失败不消耗代码修复次数。

诊断缺失时阻止猜测性代码写入，通过 `plc_diagnostics` 只读恢复精确绑定 XAE 的诊断。该工具不编译、不聚焦；接口不可用时明确报告，不偷偷以编译替代。完整诊断恢复后才解除本轮写入阻塞；错误尚存时仍需源代码进展才允许重编译。

## 边界

完整重载、继承/接口/访问权限、指针生命周期、属性访问器可用性、厂商库签名、条件编译、复杂初始化/类型别名和特定编译器版本尚未完全覆盖。遇到这些未确认情况返回 `semantic-unresolved` / `syntax-unsupported`，不能声称代码本身必然非法，也不能自动关闭门禁绕过。特别是仅能从库解析的 TON 等声明，未取得签名时会阻止写入，需要后续补充可信库元数据解析。

标准模板导入和底层 COM/CLI 的可信低层路径不是本次语义门禁的完整覆盖范围；此版本不能宣称所有工程变更入口都已有完整语义验证。实际 PLC 运行行为、调用链和业务正确性也不由本检查证明。
