# PLC / HMI 生成前准备

后端不再只要求模型“记得先查规范”：主对话和后台任务在每次生成请求前，主动构建
`GenerationContext`，将相关规则和本机工程事实附在 system context 中。
写入门禁、授权、回读、构建、浏览器和在线验证保持独立，不被这一步替代。

## PLC

- 自动加载 `.TwinCATAgent/coding_profile.json`，保留用户配置的风格和附加规则。
- 默认命名、变量分区、注释、错误处理、子 FB 周期调用规范提前给出。
- 区分事务型 / 循环服务型，避免把四件套和状态机强加给所有代码。
- 按任务自动搜索 fblib，提供候选的 family、依赖和有界声明模板；不会自动安装或创建。
- 从当前 `.sln` 精确引用的 `.plcproj` 读取库引用及解析配置、对象路径、被点名对象
  （未点名时 MAIN）的声明和成员接口。最多 20 个目录条目、3 个对象的声明摘要。
- 不自动读取整个项目实现区。目标实现、调用方及库完整 API 仍用精确工具补齐后再生成。
- 缺少模板库明确标为 unavailable，不冒充“检索后没有匹配”；便携包包含模板资产。

## HMI

- 只在当前解决方案引用的 HMI 项目内准备。多个项目未唯一指定时要求先选择，绝不拿第一个。
- 读取实际 Framework、packages.config 的逐包版本及安装包 Description/Schema。
- 自动给出常用控件或被点名控件的真实类型、常用继承属性、值 schema 和经当前包校验的文本示例。
- 属性集合是部分集合，显式标注 partial；高级控件/事件/未列出属性先用 schema/events 工具精读。
- 提前说明复杂颜色对象、StateSymbol、数组根符号及纯显示换算规则；映射/TMC 不代表 PLC 在线。

## 时效、预算与边界

- 每个运行独立持有准备器，没有跨项目全局规范缓存；短回复用运行开始时的有界近期线索路由。
- 每个模型步骤重新读取规则及相关保存文件。HMI Catalog 缓存按工程、包、schema 文件及目录
  时间戳/大小校验；任何变化后重建。新轮次和停止后重新发送都会新建准备器。
- 准备文本不存入待压缩的消息历史，每次重新附带，因此历史摘要不会吞掉规范。
- 项目事实 JSON 上限 16000 字符，每个领域 7000 字符；超大字段整项标记 omitted，
  不剪断代码/JSON。没有提供不代表不存在，也不证明目标已完整读取。
- 文件预读单文件上限 2 MiB；读取失败降级为明确 unavailable 和下一步精读要求。
- 不读取模型思考内容或工具结果中的指令；工程注释/模板描述是数据，不得授权操作或覆盖安全策略。
- 不执行 COM/ADS、不保存编辑器、不创建索引数据库、不写工程、不启停服务、不扩展工具权限。
- 只根据已保存内容准备，始终标明 `live_xae=false`、`dirty_unknown=true`；用户刚改未保存内容
  仍须当前编辑器读取工具确认。读到库引用不等于解析了该库全部接口。

## 验收

`tests/test_generation_context.py` 覆盖首次生成前注入、PLC 项目规则/成员/库解析、
停止/压缩后短回复线索、规则及源码变化、HMI schema 更新、多项目歧义、模板缺失、
预算整项裁剪、跨任务隔离、纯只读无 COM、主对话/Worker 两条接线路径及模板打包。

本机制提高首次生成的正确率，但不是对任意模型输出的形式化保证；强制写入门禁仍保留。
