# 对话图片存储与预览

2026-09-06 本地修复，基于 v1.0.8.107；未发布新安装包。

- 接受的图片原始字节保存在项目 `.TwinCATAgent/agent.db` 的 `attachments` BLOB 表，
  附件元数据只保存随机 ID、名称、类型和大小；不将 base64 写入对话 JSON 或压缩摘要。
- 原图与 SHA-256 一同保存。现有 SQLite 备份包含原图；JSON 文本导出不是原图备份。
- 图片标签可在面板内打开预览，不依赖新窗口或操作系统文件关联。
  刷新后使用已授权 WebSocket 的 `get_attachment` 读取；必须属于当前项目数据库及
  当前对话事件中的附件引用。没有通用磁盘路径读取或新增 HTTP 文件服务。
- 当前轮次的全部模型调用保留视觉块，包括工具调用后的请求。
  没有新视觉附件时，恢复当前对话事件中最近一次图片上传的整批原图，注明原始请求；
  不把全部历史图片无界塞进模型。最近一批不可读时不偷偷改用更早图片。
- 只在当前 Provider 开启视觉时发送原图。切换到纯文本 Provider 后保留预览，
  提示模型不能进行原图核对。保存的较早图片仍可在对应消息点击预览。
- 现有单图 8 MB、最多 8 个附件、单轮总量 30 MB 限制继续生效。
- 旧版仅保存文件名的图片无法从记录恢复，显示“原图未保存，请重新上传”。
  本次持久化针对栅格图片；PDF 等其他附件仍沿用现有提取策略。

边界：后台独立 Worker 不自动继承其他会话图片；分叉目前不复制 UI 事件，因此
不自动继承原图引用。清空对话后撤销其图片读取引用，但不会自动删除数据库内的孤立
图片字节；物理清理需要独立、可预览的数据维护功能，不能将数据库压缩等同于删除附件。

验证：`tests/test_image_attachments.py` 覆盖重开、压缩后恢复、跨项目/对话隔离、
完整性、缺失、事务回滚、SQLite 备份，以及三种协议在工具调用和追问后仍携带图片。
`scripts/test_industrial_ui.cjs` 覆盖真实页面的预览解码、关闭、迟到响应、旧记录及刷新回放。
