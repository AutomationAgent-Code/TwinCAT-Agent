# PLC 成员结构操作的实时基线

本次覆盖 `plc_delete_member`、`plc_rename_member`，不放宽其他结构工具，也不自动 Save/Logout/Stop。

1. `plc_read(name=所属POU,path=精确TIPC路径,structure_baseline=true)`：专用只读路径绕过源码缓存。连续两次严格读取父对象与递归成员的名称、类型、声明/实现哈希、成员清单，连同解决方案、XAE 窗口身份生成 `member_baseline`。结果保留在模型上下文，不受源码分页裁剪。
2. 用户批准删除/重命名时原样携带 `expected_member_baseline` 和父对象 `path`。未保存但携带完整基线可进入处理器；基线是否匹配由 native COM 处理器核对，不是前置层无条件放行。
3. 删除仍先做引用检查，随后在同一个 COM 调用会话内重取完整快照、对比基线，才调用 DeleteChild；重命名同样比较后才设置 Name。支持成员文件夹的相对点路径。受保护调用不会退回可能忽略新参数的旧 PowerShell 路径。
4. 成功后比对预期成员树：删除只有目标节点消失；重命名只有目标名称和可明确建模的定义头标识符变化。其他正文/成员变化报 uncertain，不自动重放或回滚用户编辑。成功返回 `written=true/verified=true` 及新 `member_baseline`，可用于下一次结构操作。编译和在线验证仍另行进行。

缺少基线的已保存旧流程仍兼容；未保存结构写必须获取新基线。接口未知 accessor（例如 type 0）、不可读文本、枚举失败、树过深/过大均拒绝签发基线，绝不把失败当空内容；这些情况不能靠 force 跳过，需人工处理或扩展有依据的类型支持。结构快照并非跨用户编辑的原子事务；执行前比较和执行后回读用于检测变化，不承诺消除 COM 调用间的全部竞态。
